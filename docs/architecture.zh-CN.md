# raradio 架构与数据契约

[English](architecture.md) | 简体中文

raradio 将人物配音配置用于可恢复的批处理：原文固定，模型负责标注，声音后端负责合成，人工集中处理异常。当前入口是本地 CLI 和 TXT，核心工作流仅依赖 Python 标准库。本文描述现有实现；尚未实现的能力列在文末，运行验证范围见 [验证记录](verification.zh-CN.md)。

## 模块边界

| 模块 | 输入 → 输出 | 负责的约束 |
| --- | --- | --- |
| `script.py` | 原文 → `Segment` 列表 | 确定性生成候选章节与朗读片段；保留原文偏移，并记录待复核的结构问题 |
| `structure.py` | 人工复核的原文范围 → 校验后的片段 | 允许显式修正章节与边界，拒绝过期编辑、范围重叠、遗漏文字和原文改写 |
| `models.py` | `Segment`、`Character`、`VoiceProfile`、`AnalysisResult` | 文本片段、人物身份、声音配置分别表示；人物不绑定某个 TTS 实现 |
| `analysis.py` | 片段 + 已知人物 → 语义类型、人物、情绪、置信度标注 | 单人模式全归旁白；规则模式采用解析器的启发式分类；Ollama 可纠正语义类型，但不能改写或重新划分原文；拒绝非法标注 |
| `project.py` | 导入、标注、配音配置、复核操作 → 持久化项目状态 | 独占写入、状态转换、缓存失效、有限重试、断点恢复与完整性检查 |
| `backends.py` | `synthesize(text, voice, emotion, output)` → PCM16 WAV 文件 | 适配实际模型能力；不支持的参数明确报错；后端提供版本标识 |
| `audio.py` | WAV + 原文 → 测量结果；已完成片段 → 章节文件 | 结构校验、波形警告、按样本拼接、SRT、来源清单及导出回滚 |

`Segment` 的 `id/chapter/chapter_title/index/start/end/text` 描述原文片段；`kind/speaker_id/confidence/emotion/reason` 描述标注。偏移是解码后文本的字符位置，读取区间为 `[start:end]`。解析器初步给出的 `kind` 只是提示：引号内容可能是书名或引用，无引号文字也可能是对白。Ollama 可按语义将 `kind` 纠正为 `narration` 或 `dialogue`，其中旁白只能归给 narrator；不确定或混有多个说话人的片段应保留待确认，不能整段硬归给一个角色。分析时原文字段和 `parse_issues` 均不可修改。

结构修正通过 `raradio structure WORK` 导出复核文档，再用 `raradio structure WORK --file reviewed.json` 应用。文档以有序范围和章节归属描述全文。这一显式操作可以修改边界和章节，无须编辑 `source.txt`。未变片段以及仅调整章节归属或名称的片段保留标注、人工确认与音频；边界或分类改变的片段重新进入分析，原有未处理的解析问题仍需复核。`resolve` 只修改整段的说话人或情绪，不修改边界。操作说明见 [文本导入与结构复核](text-input.zh-CN.md)。

这些是仓库内部模块边界，尚未发布稳定的第三方插件接口。分析器与 TTS 后端由内置名单选择，配置文件不会自动发现外部实现。

Ollama 按批次分析，携带相邻上下文和已积累人物表；项目按章保存结果。人物确认与单段人工修正独立持久化，后续分析保留已人工修正的片段。尚无完整的跨章节剧情记忆系统。

`single-voice` 是用户明确选择所有文字使用一个朗读者的模式：不调用 LLM，所有片段保留原文结构、标注为 `narrator / neutral`。它不会分析出情绪和人物归属。`rules` 是离线启发式模式，不能识别无引号对白，也不能区分引号中的书名和人物发言。分析默认只处理尚未成功分析且未人工修正的片段；使用 `analyze WORK --reanalyze` 可重做自动标注，已人工修正的归属仍保留。这两种模式均不能清除结构问题。

导入默认按 UTF-8 解码，识别 UTF-16 和 UTF-32 的 BOM；其他编码须显式指定，例如 `--encoding cp932`。`--chapters none` 可关闭标题识别。新项目未指定声音语言时默认采用 `auto`，配置时会保存该值；缺少这项元数据的旧项目保留原有 Chinese 默认值。所选 TTS 模型仍须支持请求的语言。这些选项不会把日文翻译成中文，也不会把注音、编辑注记转换为独立的朗读稿。

## 项目目录

```text
一本书的项目目录/
├── source.txt       # 解码为 UTF-8 的固定原文
├── project.json     # 数据版本、书名、原文 SHA-256、编码、切分参数、默认语言
├── cast.json        # 人物、别名、确认状态和声音配置
├── state.sqlite3    # 逐段标注、状态、尝试次数、缓存指纹、音频哈希、QA
├── voices/          # 配置时复制进来的参考音频，按内容哈希命名
├── audio/           # 逐段生成的 WAV；生成中使用临时文件
└── .write.lock      # 当前项目的写入锁
```

`cast.json` 中，`characters` 通过 `voice` 指向 `voices` 中的声音配置。旁白使用固定人物 ID `narrator`。主要角色确认一次后，置信度足够、配音可用且没有待处理结构问题的片段自动进入生成队列；新人物、归属不明、声音缺失或存在 `parse_issues` 时请求处理。

不要直接编辑 `state.sqlite3` 或替换 `source.txt`。打开项目时会核对原文 SHA-256；新版文本应导入新项目。通过配置入口更换参考音频会把文件复制到项目内，运行时不再依赖参考音频原位置。

项目变更通过 `.write.lock` 使用 POSIX `fcntl` 加独占锁，同一项目的并发写入会被拒绝。当前尚未适配 Windows 原生写入锁。迁移应在停止写入后复制完整项目目录，详见 [使用取舍与迁移](usage-notes.zh-CN.md)。

## 状态与人工介入

```text
PENDING_PARSE ──分析──→ READY ──生成──→ GENERATING ──检查通过──→ DONE
                    ↘ NEEDS_REVIEW              ├─可疑音频──→ NEEDS_REVIEW
                                                └─失败耗尽──→ FAILED
```

| 状态 | 含义与下一步 |
| --- | --- |
| `PENDING_PARSE` | 尚未完成标注；执行分析 |
| `NEEDS_REVIEW` | 仍有结构问题、分析失败、归属置信度低、人物未确认、声音配置缺失，或多次生成后仍有音频警告；按 `issue` 处理 |
| `READY` | 标注与人物声音映射可用，等待生成 |
| `GENERATING` | 已保存当前尝试；中断后再次生成时恢复调度 |
| `DONE` | 波形检查通过，或当前音频警告已被人工接受 |
| `FAILED` | 本轮有限重试仍失败；修正原因后重试对应片段 |

每段默认最多尝试 3 次，包括可疑音频的重生成；先自动尝试，再进入人工队列。再次运行不会无限重试待复核或失败片段。人物归属修正、单段重做、试听后接受音频是不同操作；“接受音频”不会代替人物确认，也不能接受已丢失或被修改的文件。

## 缓存与导出

输入缓存键包含原文片段、人物、情绪及完整声音配置；有参考音频时还包含参考文件的 SHA-256。生成指纹再加入后端版本。有效配置变化使相关片段回到 `READY`，配置缺失或人物待确认时进入 `NEEDS_REVIEW`。多个角色共用一个声音配置时，变更会影响所有使用该配置的片段。重新生成会清除旧的人工音频接受状态；生成恢复时同时验证指纹与实际音频 SHA-256。

模型标识进入缓存键，但同一路径下模型权重被原地替换不等于标识发生变化。为保证可复现，应保存所用模型版本或固定本地模型目录；依赖与模型升级后先执行一次生成检查，再导出。

导出要求全部片段为 `DONE`，并核对当前配置、后端版本与音频完整性。WAV 结构损坏或采样格式不一致时拒绝导出；人工接受的质量警告仍记录在清单中。章节文件名采用序号，不把章节标题用作路径。

```text
导出目录/
├── chapter-0001.wav
├── chapter-0001.srt
├── …
├── manifest.json    # 原片段、输入音频 SHA-256、QA、样本数和起止时间
└── playlist.m3u
```

所有章节先写入同级临时目录，完成后发布；发布失败会尝试恢复旧目录。更新导出会移除旧清单中的多余章节，但拒绝覆盖含其他文件的目录。SRT 时间来自累计样本数与段间停顿，不依赖文字估算；它是片段级字幕，不是逐字对齐。

## 后续阶段

以下能力尚未实现，工作顺序见 [实施计划](plan.zh-CN.md)。

1. **减少听检负担**：ASR 回读差异、音色相似度检查、可试听的异常队列、人物批量复核。新增检查须以真实模型与样本验证。
2. **扩展输入与交付**：EPUB、带章节 M4B/MP3、响度处理、可明确配置的备用声音、模型能力探测。
3. **长篇任务评测与优化**：跨章节人物记忆、小说标注评测、吞吐量与内存优化。

完整图形界面、ASR 与说话人身份验证均不属于当前波形 QA 的能力。后续模块的设计目标是沿用现有片段与项目数据，保留原文不可变约束。

支持日文输入和语义分类修正，不代表日语角色归属和发音质量已经达标。翻译属于独立的后续能力：需要可复核、与原文片段对应的目标语言稿，不能在分析器内改写原文，也不能依赖 TTS 的语言配置代替翻译。

llama.cpp 候选后端、当前接口与第三方插件仍缺少的能力见 [后端选择与扩展路线](backend-strategy.zh-CN.md)。
