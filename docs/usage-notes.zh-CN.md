# 使用取舍与迁移

[English](usage-notes.md) | 简体中文

raradio 当前支持本地 TXT → 角色标注 → 语音生成 → 章节导出的工作流，MLX 语音后端面向 Apple Silicon Mac。开始批量生成前，先用短样本检查角色识别、声音与耗时。安装与 CLI 命令见 [使用手册](handbook.zh-CN.md)，数据契约见 [架构说明](architecture.zh-CN.md)。

## 一次配置，之后处理异常

1. 先导入一个短章节，完成角色分析。确认旁白与主要人物的 ID、明确别名和声音映射；不要把“他”“她”这样的泛指代词当作某个人的固定别名。
2. 为每个主要声音生成少量代表句：平静叙述、普通对白、强情绪、较长句与人名。听过后固定配置，避免整本生成完才发现音色不合适。
3. 运行批量生成，重复运行可续接。正常片段无需逐条确认，系统先做有限重试。
4. 查看异常队列：归属问题修人物，配置问题修声音，失败片段单独重做；只有实际试听认可后，才接受可疑音频。
5. 全部片段完成后导出章节 WAV 与 SRT。需要保留试听笔记时，放在导出目录外，避免阻止后续导出替换。

“配置一次”指同一本书已确认的角色与声音可以复用。新角色、指代歧义或模型失败仍可能需要处理；规则分析模式会把对白留待确认，不能作为整本小说的自动角色识别方案。

## 先选择声音能力

下表描述当前适配器实际接受的能力，不表示所有 TTS 模型都具有同样接口。

| 路线 | 适合验证什么 | 当前边界 |
| --- | --- | --- |
| Qwen3-TTS CustomVoice | 预设声音、角色区分、情绪与语气指令 | 使用模型支持的预设 `speaker`；不接受克隆参考音频；情绪指令效果仍需试听 |
| Qwen3-TTS Base | 参考音频带来的音色相似度 | `strict` 要求 neutral；`reference` 允许保留其他情绪标注，但不将其用于控制合成；均不接受 `instruct` |
| 诊断音 `tone` | 状态恢复、缓存、章节拼接与字幕 | 输出正弦波，不是人声，不可用于评价有声书听感 |

当前 MLX 适配器要求显式指定模型，支持 Base 与 CustomVoice，语速参数要求 `speed=1.0`。不支持的能力会报错，避免参数看似接受却未生效。

Base 的 `icl` 克隆模式需要参考音频及其准确转录，并要求模型包含所需编码器；`xvector` 模式使用声音特征，不使用参考转录。参考文件在配置时复制进项目。选择 Base 时，`emotion_mode: reference` 允许保留分析得到的情绪标注，但不把标注发送为合成指令，也不保证参考情绪或韵律迁移。需要情绪指令的角色，可使用 CustomVoice 并试听验证效果。

参考转录必须对应音频实际说出的内容，不能用译文代替原语种转录。使用跨语言参考录音时，需要分别验证音色相似度、目标语言发音和情绪效果。

## 质量检查能说明什么

目前自动检查 WAV 是否可读取、是否为 PCM16、是否为空或存在数据截断，并标记静音、稀疏信号、削波和异常时长。这里的数据截断指文件结构与样本数量不完整，不能覆盖所有语音漏读。时长窗口较宽，用于发现明显问题。

这些检查不能判断漏读、错读、重复句、专名发音、对白归属或音色是否正确。原文不会被分析器改写，也不代表合成器一定逐字读对；波形 QA 通过不等于 ASR 校对或说话人身份验证通过。

有限重试能处理偶发生成异常，不能修复不支持的后端参数或不存在的参考文件。重复出现同一错误时先修配置；不要为了清空异常队列批量接受未听过的音频。

## 本地运行与资源

文本分析默认连接本地 Ollama，MLX 在本地合成，工作流不要求持续调用付费 API。模型文件和可选依赖需要另外准备；模型加载、速度与声音效果以实际样本为准。

内存需求取决于模型、量化方式、输入长度和同时运行的进程，项目尚未给出通用的最低内存基准。可先完成文本分析，再运行语音合成；CLI 在 Ollama 分析结束后会请求卸载所用模型，卸载失败时会提示。记录短章节的耗时、重试次数、异常比例与试听结论，用于判断当前配置是否适合更长任务。

## 换电脑或归档

1. 等当前写入结束，或正常停止生成，之后复制整本书的项目目录。不要在数据库与音频仍在更新时拆开复制。
2. 保留 `source.txt`、`project.json`、`cast.json`、`state.sqlite3`、`voices/` 和 `audio/`。只复制导出 WAV 能继续收听，但不能恢复逐段生成状态。
3. 在目标机器安装 raradio 及需要的可选后端，准备原来使用的模型；模型缓存与 Python 虚拟环境不属于书籍项目。
4. 检查声音配置中的模型标识。若使用绝对模型路径，按新机器位置更新；项目内参考音频已使用相对路径。
5. 先查看状态，再运行少量生成检查。有效缓存会复用；模型配置或后端版本变化会使相关生成指纹变化，需要重新生成后验证。

项目写入锁依赖 POSIX `fcntl`，尚未提供 Windows 原生实现；MLX 语音后端面向 macOS / Apple Silicon。复制数据不代表所有目标操作系统都具备同等后端支持。跨机器保持相同原文、配音配置、参考音频和模型版本，有助于继续处理；更换运行环境后仍应抽听样本。

EPUB 导入、M4B 成书和完整试听界面尚未实现，后续方向见 [实施计划](plan.zh-CN.md)。
