# 测试与验证

[English](verification.md) | 简体中文

测试分为无需模型的工作流检查和真实模型验证。工作流测试通过只能证明相应契约，不代表小说人物识别、逐字读音或克隆相似度已经达标。

## 无模型测试

在源码根目录执行，使用 Python 3.11+ 和提供 `fcntl` 的 POSIX 系统：

```sh
python3 -W error::ResourceWarning -m unittest discover -s tests -v
sh -n setup.sh run.sh
```

测试覆盖原文偏移与切分、结构化标注、人物确认、单人朗读、缓存失效、有限重试、中断恢复、单写入者、参考音频导入、CLI JSON 输出、WAV 检查与原子导出。MLX 契约测试替换模型加载和推理结果，不需要安装 MLX 或下载权重。

公开示例也纳入回归：全部五份 TXT 与七份 cast 模板参与实际工作流检查；离线教学脚本通过真实 CLI 演示双章节、五个引号片段的人工归属、限量续跑、单段重做和仅小雨声音的局部重生成。测试检查音频内容、修改时间与输出清单，避免把重新生成误判为缓存复用。

```sh
python3 examples/offline_workflow.py
```

脚本默认在 `work/` 中创建唯一新目录，保留 `book/`、`export/` 和 `verification.json`。归属来自原创样例的已知答案，不能用于任意小说的自动人物识别，输出也只是诊断音。人工操作说明见 [复核与换声音](../examples/workflow.zh-CN.md)。

也可以用公开示例复现完整的诊断流程：

```sh
python3 -m raradio build examples/demo.txt --work work/verify-core \
  --analyzer rules --cast examples/cast.tone.json --output output/verify-core
python3 -m raradio build examples/story.txt --work work/verify-single \
  --analyzer single-voice --cast examples/cast.tone.json --output output/verify-single
```

第二条命令检查含对白的单人模式。两份输出都是诊断音；检查导出文件齐全后，重复命令，确认有效片段没有重新合成。

## 真实模型验证

按 [使用手册](handbook.zh-CN.md) 准备环境、模型和参考录音，使用 [示例目录](../examples/README.zh-CN.md) 的短文与模板。每种分析方式使用不同工作目录。先验证预设声音，再分别验证 xvector、ICL 和混合配音。

提交可复现的验证结果时记录：

- raradio 版本或提交、Python 和系统版本、硬件型号与可用内存。
- 推理库版本、模型仓库及固定 revision，或本地模型文件哈希；不要公布个人绝对路径。
- 原创输入短文、脱敏后的完整配置、实际命令、退出码及片段状态。
- 生成耗时、音频时长、自动检查结果，以及人工听到的具体问题。
- 续跑是否复用音频、改单个声音后是否只重做相关片段、中断后能否恢复。

参考录音未获公开授权时不要上传；另选可分享的材料建立复现。参考音频、模型缓存、工作数据库和生成结果不随仓库分发，所有示例都应从公开输入重新生成。

## 仓库验证

GitHub 源码仓库包含 CLI、文档、测试、配置示例、运行脚本、随包 Agent Skill 和许可说明，并排除工作数据库、录音、模型权重、个人配置、生成结果与虚拟环境。

GitHub Actions 已配置 macOS/Linux、Python 3.11–3.14 的无模型检查与锁定核心安装。手动选择的 MLX 任务检查可选依赖安装与一致性，不下载模型。本次未在 GitHub 云端执行这些工作流，因此 Linux 平台仍保留待验证状态。临时副本中的错误模型类型、参考路径错误、角色映射丢失与声音互换等变异均能被示例回归测试捕捉。

## 开源打磨验证（2026-09-12）

CLI 与安装审查后，macOS 上使用 **Python 3.11.15 和 3.13.14，分别通过 112 项测试**，并将 `ResourceWarning` 视为错误；shell 语法检查通过。新增回归涵盖离线 doctor 与失败退出码、非法服务地址、创建项目前的参数验证、损坏项目错误、含空格的调用者相对路径、安装环境选择，以及音频丢失或后端版本改变后的限量续跑。

全新核心源码环境创建成功；uv 0.6.5 与 CI 固定的 uv 0.12.13 均通过 `uv lock --check --offline`。另一个全新 Python 3.11 环境使用公开缓存安装锁定的 MLX 依赖：共 56 个已安装包，通过 `uv pip check` 和 `doctor --profile mlx`。在本次 Apple Silicon Mac（macOS 26.6.2）上，单独导入 `mlx.core` 与 `mlx_audio.tts.utils` 成功，Metal 报告可用。这没有加载权重、合成新语音或验证首次模型下载，也不能证明 macOS 14 或云端虚拟机行为相同。

本轮还检查了版本一致性，以及通过源码 runner 生成诊断音。当前源码更新检查见[维护指南](maintenance.zh-CN.md)。CI 矩阵仍属于已配置的覆盖范围，不代表已在云端执行；本次没有创建 Git 发行版本。

## Agent 工作流验证（2026-09-12）

Agent 支持增加了两项 CLI 发现入口测试。在此检查点，包含并行文本流程改进的工作目录在 **Python 3.11.15 和 3.13.14 上分别通过 153 项测试**。随包 Skill 通过 frontmatter 校验，并在源码环境中通过 Markdown、JSON 与 `importlib.resources` 暴露相同内容。

给独立 Agent 的输入只有源码环境准备出的可执行文件、`agent-guide`、原创中文双章短文，以及期望结果。它没有使用分析器或下载模型，自行配置旁白/角色各自的诊断音声音，确认归属，处理两段生成上限，最终完成十段并导出两章。只把李禾的诊断音语速改为 1.2 后，仅她的一段对白重新生成；其余九段音频的路径、哈希与修改时间保持不变，输入和保存原文的哈希也一致。评估 Agent 没有报告阻碍执行的说明问题。

这次演练验证了一个小型诊断任务的 CLI/Skill 协作与局部修订，不代表认证所有 Agent 客户端、自动发现、长篇推理、真实语音或试听能力。Agent 使用自身已有的推理能力；raradio 没有提供 Agent API 或外部标注导入器。修改指令或工作流后，可根据 [随包 Skill](../raradio/skills/raradio-audiobook/SKILL.md) 重复此类独立演练。

## 首次提交前最终审查（2026-09-12）

针对项目状态、适配器、打包和双语文档的独立审查发现三处问题：HTTP 协议异常绕过 Ollama 错误处理、无效声音字段类型可能覆盖有效配音配置，以及参考录音重复导入中断时可能损坏已有副本。回归测试先复现问题，再实施修复。修复后统一处理传输异常，在修改前校验配音配置，并复用校验通过的录音或在哈希验证后保存完整副本。后续复核未发现这些改动仍有阻塞项。

修复后的工作目录在 macOS 的 **Python 3.11.15 和 3.13.14 下均通过 160 项无模型测试**，并将 `ResourceWarning` 视为错误。Shell 语法和离线锁文件检查通过。中英文手册已与显式编码、结构修复和重分析命令保持一致。本轮审查不新增真实模型推理或试听质量结论。
