# 开源就绪程度审查

[English](open-source-review.md) | 简体中文

审查日期：2026-09-12。raradio 面向喜欢终端和自动化的人，目标是容易安装、便于修订的有声书制作工具。本次检查源码、CLI、环境准备、文档及同类工具的上游说明，不构成音质对比评测。实际执行证据见 [验证记录](verification.zh-CN.md)。

## 总体判断

项目有自洽的 Alpha 范围：零第三方运行依赖的制作核心、显式配置、可恢复的片段状态，以及可选的本地语音后端。适合愿意确认角色并试听、使用受支持 Mac 的开发者。目前不能承诺任何人、任何机器拉取源码后都能生成人声。安装脚本可以准备 Python 包；硬件、模型下载、内存及模型能力仍是独立条件。

值得强调的是通过 CLI 持续修订制作项目。CLI 转换、多声音和续跑在其他项目中也存在。更简单、更可靠、更快或音质更好的结论，需要统一任务与测量支持。具体替代方案见 [同类项目](reference-projects.zh-CN.md)。

测试会复现 CLI 失败并实际运行 shell 脚本；只检查源文件文本不足以证明行为。配置了云端工作流，也不等于它们已经在 GitHub 上通过。

## 后续优先级

1. **在干净 Mac 上验证受支持的语音路径。** 记录 macOS、Python 和原生库版本、联网安装、下载、原生库/GPU 初始化、预设语音与再次离线运行。语音相关公开更新前检查锁定版本。当前核心测试不覆盖原生推理。
2. **简化最常见的编辑操作。** 单人朗读仍需 cast 文件，改角色仍需整表 JSON 导入。后续可以通过声音预设命令、定向角色编辑减少常规 JSON 操作，同时保留完整 JSON 导入导出用于复现；没有具体需要时不引入第二套配置系统。
3. **验证工作流是否真正省事。** 发布含两个角色的原创短章，记录安装步骤、首次可用音频耗时、人工决策数量、纠正一句归属、换一个声音、中断续跑及重新生成的片段数。与至少一个 CLI 工具在明确版本下比较，关注人工处理成本与生成速度。
4. **按实际需求扩大范围。** CPU/Linux 语音后端比 UI 更能扩大可用人群；EPUB 与带章节的压缩格式可减少输入输出准备。每个扩展都需明确能力检查和集成证据，目前均未实现。
5. **验证公开历史。** 源码已整理为一个本地根提交，并配置预期的 GitHub 远程地址。首次推送后运行云端检查；如创建 GitHub 标签或 Release，按[维护流程](maintenance.zh-CN.md)确保它们对应已审查提交。

## 依赖与兼容边界

- 核心支持 Python 3.11+ 和提供 POSIX `fcntl` 的系统；macOS 有本地执行证据，Linux 已配置 CI，等待云端结果。Windows 原生不支持；可以查看帮助和版本不代表可操作项目。
- 源码安装推荐 Python 3.11。当前人声仅支持 Qwen3-TTS Base/CustomVoice 经锁定版本的 MLX-Audio 在原生 Apple Silicon、macOS 14+ 且可访问 Metal 的环境运行；未接入 CPU、CUDA、Intel Mac 或 Linux 语音后端。
- `uv.lock` 固定解析出的 Python 包集合，不锁定 Python 本身、Ollama、模型权重、系统库、硬件或所有隔离构建工具。
- `mlx` 可选依赖组带平台条件；`setup.sh mlx` 与 `doctor --profile mlx` 还会检查实际平台，避免把依赖解析结果误认为语音已受支持。
- 模型可能在首次使用时下载。核心很小不代表完整语音环境也很小。需要以所选模型验证缓存、下载访问与可用内存；同名或同路径替换模型时，不会自动以权重内容重新计算缓存标识。
- 项目格式仍为版本 1，不支持的格式会被拒绝；没有通用迁移工具或稳定 Python/插件 API。可能影响状态的升级前，应停止写入并备份完整工作目录。
